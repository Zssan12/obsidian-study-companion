# Architecture

Markdown lessons capture an explicit document/selection snapshot in SourceContext.markdown. The Obsidian adapter reads the matching open editor (including unflushed edits), otherwise the captured vault path; selection planning never expands to the file. Empty inputs and inputs above 60,000 UTF-16 code units fail without truncation. Independent bounded outline calls cover every text segment; generated topics contain titles and objectives with empty page arrays, never invented PDF pages. Long topic explanations reuse the shared evidence budget and disclose compressed evidence. These input guarantees do not guarantee semantic coverage by the model. Ordinary questions retain existing source-routing rules and do not read the full note just because a directory exists.

Live Markdown edits/selections do not invalidate a saved directory. Explicit teaching resolves the current durable plan and uses its original snapshot; mismatched explicit snapshots and stale plan IDs are rejected. Replanning reads current content, preserves the ordinary draft, and replaces the active pointer only after successful plan persistence. Cancelled preparation or a switched/closed composer never dispatches. Snapshots, outlines and teaching progress round-trip through private history.json; original notes are not rewritten. PDF evidence matching, page rules, main/Quick Ask ownership and explicit-only visible note export remain intact.

CramModal provides an explicitly started, independent multi-PDF export workflow. CramGenerator captures a separately owned backend configuration, processes one immutable CramPdfReader binary snapshot at a time, and never receives or updates conversation/session/history state. Text is segmented without truncation and sequential calls contain at most eight segments, a bounded text budget and two images; textless pages render automatically, while reading images on every page is an explicit option. Requests use the existing deadline and native tool restrictions, with no resumed session, retrieval or web access. Each completed file (or completed batches of an interrupted file) is exclusively created under a new Study Companion 突击 run directory. A generated index records complete/partial/failed/cancelled status and refuses to overwrite intervening user edits. Stop/close cancels future work; errors are per-file, no automatic retries or restart resume. The original PDFs remain outside this export and are neither copied nor changed. Standard model-generated content is not semantically validated; supplied page coverage describes inputs processed, not a guarantee that every claim is correct.

Main and Quick Ask composers accept local file drops, an explicit file chooser, and pasted images. `FileDropZone` handles browser gestures; `AttachmentControls` owns pending feedback, limits, deduplication and draft-scope invalidation. Importing never sends, switches the study source, or starts a model request; submission is blocked until imports finish. `AttachmentImporter`, injected by main, copies supported UTF-8 text, PDFs and normalized PNG images into `Study Companion Attachments`. PDF imports reuse the explicit page picker. Unsupported formats and oversized content fail visibly; cancelled imports or removed references do not delete local copies. Images are bounded to 2048 pixels on the longest side and 3 MB after conversion, with two images and three total attachments per draft. Source contexts persist only an image SHA-256 reference, not base64. At dispatch, an injected reader checks the local image version and supplies actual PNG payloads to either backend; missing or modified images fail rather than degrading to filename-only answers. Direct-answer mode rejects new image input. Image attachments and PDF visual evidence share the backend's two-image budget. Saved history retains references, not a promise to reload old images into every future request.

Answer selections offer two distinct actions: “追问” prepares an editable explanation prompt and the full selected text as a Markdown blockquote in the original conversation's input, while Quick Ask retains its independent side-conversation behavior. Neither action sends automatically: the user edits or confirms with Send. Existing custom drafts are preserved before the appended prompt, repeated clicks do not duplicate the quote, and oversized drafts fail without truncation. Main followups retain an `answerRecordId`-marked attachment for provenance and routing, select the owning unit, and temporarily retain study-source focus with a notice; the next explicit file-open releases that retention. Quick followups reopen the exact recorded conversation ID; with an unsent custom draft, its original context is retained and the new answer quote is added as an attachment. Selection ownership is captured before button focus; removed records and reset main-history epochs are rejected on click rather than silently routing to a new context. Answer quotes remain explanatory material, not source evidence. Evidence routing ignores only exact blockquotes matching the supplied answer references, not the user's surrounding question or explicit source requests.

Main auto routing distinguishes model-answer quotes from source attachments. With compatible conversation history, ordinary explanations of quoted answers (including quoted formulas) use conversation context without new PDF preparation or retrieval. Explicit source/verification/search requests, real source attachments, source-only mode and lesson actions retain the evidence path; ambiguous questions remain conservative. Composer preflight and controller dispatch share this policy. Conversation-only prompts retain answer quotes and label them as model text, while excluding new source attachments; quote paths do not imply PDF evidence. Existing history scoping, invalidation and overflow summarization remain unchanged, so skipping evidence preparation is not a guarantee of one model call for arbitrarily long history.

PDF requests and explicit answer followups refresh durable records before deriving lesson/followup inputs; changes during asynchronous preparation reject stale history-derived instructions before answer dispatch. Successful private Codex checkpoints retain metadata for PDF evidence actually supplied to that thread. Main citation validation combines current pages with retained same-version pages, never all historical record metadata. A changed PDF hash forces reconstruction with no inherited page allowance. Quick Ask keeps current-selection citation scope. This tracks supplied source identity, not semantic entailment or verbatim retention after compaction.

Indexed text-PDF retrieval now plans bilingual query terms and selects page identities from the current lesson catalog (or bounded per-page headings when no catalog exists). The bounded, cached planner emits validated JSON only; answer evidence is reloaded original page text, never planner-generated prose. Catalog batches cap at sixteen. An unavailable planner fails visibly; semanticPlanning:false is a compatibility/testing path, not the production default.

PDF outlines now generate coarse, single-level learning topics directly from original page text. A token-budgeted batch (30,000 estimated content tokens plus prompt headroom) replaces the old 20,000-character batches and subsequent chapter-grouping model call. Typical slide decks can fit one call; oversized documents retain sequential cached batches and page-segment coverage. Each batch requests 4–8 topics (fewer for short content), validates a maximum of eight and coverage of every readable page, and bounds output to 6,000 characters. This is navigation granularity, not a claim of exhaustive semantic coverage. Existing grouped outlines, stable topic identities and progress remain readable without migration. The UI uses compact title/page-range rows and hides skip/reorder controls inside per-topic management menus; legacy chapter expansion is preserved and reordering stays within those chapters.

PDF text-layer selections capture file-order sourcePages from both selection endpoint page containers; missing or unsupported page identity stays absent; page labels appear only when a page identity is available. This does not grant whole-page or image access. sourcePages and answerRecordId round-trip in records. Final PDF Markdown/wiki/HTML link targets are checked against per-source supplied-page allowlists; invalid links are removed and the record is marked failed. This checks identity/range, not semantic entailment. A final currentQuestion envelope follows history so old requests do not become the current task.

SelectionExplain installs one document-scoped toolbar per Obsidian window. DOM selection captures text, bounded nearby paragraph and originating leaf/record before asynchronous work. Main and side saved-answer roots expose record IDs; the composition root resolves their original unit, rechecks record existence and stores answerRecordId in SourceContext. These excerpts are model output, not original-source evidence. Toolbar activation opens Quick Ask with a prepared editable explanation question; only explicit confirmation/send calls the backend. Selecting alone never calls the backend. Same-unit popovers reuse the durable side identity, reject replacement while generating or holding an unsent draft, and support expanded reading. Document listeners are disposed on plugin unload.

budgetEvidence reserves room for instructions and history, shares an estimated 40,000-token evidence budget across primary and attachments (primary has twice the weight), redistributes unused shares, and summarizes all segments of oversized inputs with explicit summary labels. It never silently drops an attachment. The final prompt is rebuilt after PDF attachment resolution. Managed history first passes all completed durable exchanges directly when they fit the remaining prompt budget, including reservations for the current question and hidden followup instructions. Only overflow triggers summaries of older exchanges; cached summaries emit no generation progress. Recent complete exchanges and related excerpts are bounded by the remainder, and original answer bodies are never rewritten. See docs/long-context.md. Estimates are conservative character heuristics, not exact tokenizer or image-token accounting. Direct-answer policy discourages needless source-switch confirmation; Quick Ask policy also applies after visual evidence preparation.

Study Companion is a standalone desktop Obsidian plugin. It supports Markdown selection questions, per-source main sessions, isolated Quick Ask conversations, and readable records through Claude or Codex CLI backends. Optional local scanned-page OCR is described below; fork optimization and cross-device CLI session sync remain deferred. Automatic scoped Markdown retrieval and isolated native web lookup are implemented; see docs/learning-tools.md.

CLI path discovery inspects known executable locations without launching probes. Windows Codex discovery supports native executables in current and legacy npm vendor layouts for x64 and ARM64; shell wrappers and WSL are not launch targets. The settings page can fill blank paths after installation and explicitly select the default provider for future conversations; existing paths and conversation ownership are preserved.

Dependencies: UI -> application -> core; adapters -> core. main.ts is the composition root. Core ports are defined in src/core/contracts.ts. Use-cases own session routing and cancellation. Obsidian supplies explicit selection context; the backend does not browse the vault directly. LearningTools executes validated Glob/Grep/Read requests through a read-only VaultSearchPort.

StudyUnit.id is stable; sourcePath can change; CLI sessionId is a replaceable backend reference. A quick conversation has its own conversationId and backend session ID. Only main requests update mainSessionId. Requests capture their destination before execution; there is at most one active main request per unit and one active Quick Ask globally.

Conversation mode is explicit on new normal units and records; absent mode remains study for backward compatibility. A normal unit has no source path and owns its own main session. Normal chat accepts the explicitly selected Markdown text as optional source evidence, strips its surrounding paragraphs, and file focus never retargets its unit. Both modes support selection-based Quick Ask: the popup captures its unit/mode and selection at opening, then continues its independent conversation even if the main panel changes modes. Study main questions still require a matching source; normal Quick Ask retains its explicit source citation without binding the normal main conversation to that file.

Snapshot errors carry unit, kind, conversation, and request IDs. Each conversation retains its latest error independently; a new request or main-session reset clears only that scope. UI status reads the matching conversation. Unsaved records survive refreshes in process memory; a refresh failure after successful creation does not create a recovery record.

Context usage is keyed by unit, main/Quick Ask kind, and conversation ID, persisted in StudyState.runtimes, and restored on controller initialization. StudySnapshot.runtimes exposes these independent reports; each composer selects its own scope. Partial runtime/done events merge only within that scope and provider, including interleaved requests. Main-session reset and conversation deletion/restoration invalidate and persist removal of only the affected report. Restored values represent the backend's last report, not a fresh measurement. Older conversations without saved reports remain unknown until a new backend report; historical call consumption is not used to invent current context occupancy.

JsonStudyRepository stores new complete exchanges, collection metadata and review status in one plugin-private history.json; ordinary chat never creates visible Markdown. PluginHistoryFile uses exclusive first creation and DataAdapter.process for atomic updates of the latest disk contents. Mutations serialize, duplicate identities are rejected, and malformed envelopes fail without overwriting data. Individual malformed records are diagnosed and retained through unrelated writes. MarkdownStudyRepository remains the in-place compatibility reader/writer for existing Study Companion records; no implicit migration, copying or deletion occurs. Reads combine both stores, with private IDs taking precedence, and never reconstruct missing records from memory. Only explicit notebook/export actions write visible notes. The composition root keeps settings and stable study-unit state in its existing serialized saveData path, separate from history.json. Backups and migrations must include the plugin directory.

Malformed record files are skipped individually during listing and retained unchanged. The repository exposes path-specific diagnostics, and the composition root reports changed diagnostics through an Obsidian notice. A malformed record does not prevent plugin initialization or reading other records; general storage failures still propagate.

First increment uses independent side sessions and bounded source excerpts. Historical source text remains with each record. SDK sessions are machine-local; readable notes survive session loss. Automatic writes are limited to plugin-created learning records and metadata; user-confirmed answer append may also write to an explicitly selected existing Markdown note, and explicit answer saves or confirmed notebook supplements may create or update a source-owned Markdown notebook; native filesystem/shell tools remain disabled; isolated web requests allow only native web tools. The optional PDF evidence workflow executes only application-validated read requests. No telemetry, token handling, automatic retries, or background model requests.

The desktop bundle injects Node timer functions and Node's AbortController constructor for SDK compatibility with Electron. These aliases remain local to the bundle; shared Node APIs and host browser globals are not patched.

Model and effort controls share persisted plugin preferences across the main composer and Quick Ask. The composition root serializes preference patches with repository state saves and publishes changes only after saveData succeeds. Each backend run captures its configuration before awaiting SDK initialization; later changes apply to subsequent requests and preserve existing session IDs and conversation isolation.

Codex model choices are available before the first request. The composition root injects local bundled-catalog discovery into both composers, sharing in-flight and successful reads by configured CLI path. Discovery uses the same restricted child environment as answering and never creates a model request or remote catalog refresh. Late discovery results cannot overwrite a switched or closed composer. “CLI 默认” remains an explicit unspecified-model option, not a claim about account availability or the resolved model.

Backend provider belongs to the conversation: StudyUnit.provider persists main ownership and StudyRecord.provider persists each Quick Ask ownership, including failed requests without a session. New conversations inherit the configured default provider without a modal; only explicit resets and ambiguous legacy session ownership require selection. New Quick Ask inherits the main provider and shared model/effort preferences without a modal; an existing side conversation retains its provider. StudyUnit.quickConversation persists the active side conversation ID and provider before its first request. Reopening reuses this identity, or adopts the latest legacy side conversation; only explicit new creates another. Concurrent ordinary openings converge through serialized state writes. Historical records remain independently accessible. Main submissions reject a different provider; Quick Ask checks persisted ownership even before an answer exists. Notebook generation uses the main conversation provider in an independent request.

BackendRouter routes explicit request ownership before legacy session evidence. An opaque versioned session reference preserves separate Claude and Codex IDs; legacy untagged IDs belong to Claude. A single legacy session is adopted automatically; an unbound dual-session conversation requires a one-time choice without clearing either reference. The router rejects ambiguous dual sessions instead of using mutable preferences. New conversation resets the current unit's main backend references and selects its new provider, retaining durable history; it does not create multiple main conversations or replay old records. Closing the creation modal leaves the conversation unchanged; plugin unload cancels open creation modals.

Codex runs the official CLI's `app-server --stdio` in a plugin-owned temporary directory. Unlike the earlier exec integration, it loads the user's CLI connection/model configuration and rules; provider routing can therefore follow a configured gateway. The client initializes, reads effective settings without logging/persisting them, and uses only MCP entry names to set `mcp_servers.<name>.enabled=false` for thread/start or exact-UUID thread/resume. Authentication stays inside the CLI; no credential endpoints or credential files are accessed by the plugin.

Agent-message deltas are forwarded immediately, scoped to the returned thread and turn IDs. Completed snapshots append only an unstreamed suffix; inconsistent snapshots fail rather than duplicate or silently alter text. Per-turn usage uses tokenUsage.last. Recoverable reconnects become progress; failed turns remain errors. Each request keeps its original conversation. All fresh threads must confirm ephemeral:true before model dispatch. Successful Codex answer turns can retain their App Server connection and use turn/start on the same private thread for later questions and topic explanations; helper/planning/web calls remain independent. Captured backends freeze configuration while sharing the root-owned pool (at most eight idle connections, LRU eviction). Disposing a successful capture preserves its idle connection; root disposal closes the pool. Cancellation, partial failures, protocol violations and early consumer termination invalidate the connection, terminate the process, escalate to SIGKILL if needed, and wait for exit. Temporary images/catalogs are retained. Both child environments preserve explicit proxy/CA variables while excluding credential variables, NODE_OPTIONS and TLS bypass flags. This transport requires a compatible App Server protocol (locally checked with CLI 0.154.0).

Composer slash templates insert editable text without sending. Both composers expose only file/image import in the attachment menu; selection capture and answer references remain independent. The removed selection/note/PDF menu actions and their generic picker dispatch are gone. PDF range selection remains part of importing a PDF and PDF Quick Ask. ## Bounded PDF evidence workflow

`PdfEvidenceAgent` is an application use case injected into `StudyController` at the composition root. It is explicitly enabled through the `pdfEvidenceAgent` preference (default false), captured when submitting. It applies to study PDF questions without active lesson processing or extra attachments. Ordinary/lesson/attachment flows retain their existing independent text path. `resolvePdfQuestionRoute` is shared by dispatch and composer previews. Both composers disclose visual versus text handling and the fallback reason, refresh on settings/attachment/question changes, and reject scan-only PDFs in a text route (including attachments). Enter and form submission use the same preflight; the controller independently enforces it before provider persistence or any backend call. First-PDF promotion and typed lesson commands are included in main previews. Quick Ask only supplies its own durable history to the planner; main supplies its own last three exchanges, bounded to 9,000 characters.

The core `PdfEvidencePort` opens an immutable in-memory PDF snapshot; the Obsidian adapter implements it using the existing `PdfReader`. Page selection stores an optional backward-compatible SHA-256 in `SourceContext.pdf`. Agent requests require a fingerprint and compare it and the extracted selected text before model calls. Missing/moved/modified sources fail without substituting another file. Selected pages remain the read allowlist (not the whole vault or an implicit whole document).

A model emits strict JSON actions (`search_document`, `read_pdf_page`, `read_page_region`, `answer`). New `answer` actions must include `evidenceStatus: sufficient|insufficient`; omitted or invalid status fails validation rather than implying sufficiency. The trace and final prompt preserve insufficiency and its missing-evidence reason. Storage still accepts historical answer actions without this field; their original status is retained, not reinterpreted from free-form prose. The application validates each action and executes only scoped PDF reads; CLI native tools stay disabled. The planner is not MCP/function-tool integration. It receives a page index, an initial bounded excerpt, observations and any requested images in isolated calls without a session ID. Four tool actions, two PNGs, at most five planner calls, duplicate-action detection and bounded text/output/image sizes prevent unbounded execution. Crops use normalized page coordinates, minimum region width/height 0.05, and a maximum rendered edge of 1600 pixels. Text snippets explicitly disclose truncation. No retry/repair loop is used.

Final answers use captured ownership. Indexed PDFs and long history use application-managed scoped history without resuming CLI sessions; short legacy conversations may resume. Configuration is captured for multi-call operations and cancellation prevents subsequent stages. Auxiliary context-call usage is not a complete cost ledger.

`StudyRecord.evidenceTrace` persists a validated, versioned trace with scope, file fingerprint, actions, text results, image labels, elapsed time and usage. PNG bytes are not stored in the Markdown record. The final answer footer lists actual evidence pages; explicit PDF Markdown links are range-checked. Semantic entailment is not enforced by this structural check. Historical images are not replayable from Markdown alone; the fingerprint identifies the version but does not archive the PDF binary.

Claude sends Base64 image blocks via SDK iterable user input. Codex writes exclusive UUID-named PNG files with mode 0600 to its owned temporary directory and passes them as App Server `localImage` inputs on new or resumed turns. No view-image tool or arbitrary file access is enabled. Temporary images and directories are retained, consistent with the no-recursive-cleanup policy. The owner may remove them manually. This is on-demand visual reading, not an OCR index or a runtime-loadable Skill system.

LearningTools captures the user-selected retrieval scope and web permission at submit time. New settings default to the current source only and conservative automatic web availability; existing valid choices, including web disabled, are preserved. Web eligibility uses the current question and only the immediately previous exchange of this unit/kind/conversation/provider/history epoch. Ordinary selected questions bypass retrieval planning regardless of whether the saved scope is source, folder or vault; access scope is not a request to search. Only explicit note lookup or eligible web requests enter planning for a supplied selection. Unbound normal chat bypasses web planning. Eligibility is a bounded text heuristic, not semantic classification or a requirement to search. ## Offline selection dictionary

SelectionExplain also performs automatic English–Chinese lookup for short English selections in PDF text layers, Markdown source/preview and rendered answers. DictionaryPort is a separate local-only core port; main.ts injects one LocalDictionary instance shared across Obsidian windows. Lookup does not depend on a study session, dispatch a model request, send network traffic or persist selected text. Existing Quick Ask/followup actions retain their explicit activation and captured conversation ownership.

The adapter lazily decompresses bundled ECDICT prefix shards and shares in-flight reads through a 24-shard LRU. Exact spelling precedes case folding, and dictionary-provided inflection aliases resolve to their headword; PDF line-wrap hyphenation is normalized only for lookup. UI revision checks discard late results after reselection, dismissal or disposal. Definitions render as plain text in a viewport-bounded popup. Missing entries and local failures stay visible without automatic online fallback. This provides dictionary words and recorded expressions (at most eight words/100 characters), not whole-sentence/context-sensitive translation or OCR of image-only PDFs. The pinned data source, build script and MIT notice ship with the source; the license is retained in main.js.


When exact dictionary lookup misses, the UI first tries to recover the same contiguous English word from the captured DOM range endpoints; this only affects dictionary lookup, never the saved source quote. If that recovered word has no entry, single English fragments of 3–48 letters additionally search the same two-letter prefix shard. Trailing completions (up to eight extra letters) precede single-edit corrections (including adjacent transposition, at least five selected letters). At most five real dictionary headwords are returned; case duplicates and aliases are excluded. This is a bounded local heuristic, not arbitrary spelling repair: first-two-letter errors, short fragments and phrases are not fuzzy-searched. A 256-query LRU shares and retains suggestions. UI labels the initial candidate as “可能是”, retains the originally selected text, and lets users switch candidate definitions without a model request. Exact entries never trigger fuzzy lookup, and UI revision guards also cover late suggestion results.

Clearing the current main conversation uses durable deletion markers and advances the history epoch. A validated retainedLessonPlan in unit state preserves only directory navigation; prior exchanges stay excluded from reconstructed prompts and progress starts over. Replanning replaces that retained catalog. Favorites are exposed separately from visible chat records. Permanent deletion is available only for already deleted, explicitly confirmed record identities: JsonStudyRepository compares current decoded records and atomically removes them from private history.json. Favorites block permanent removal until explicitly unstarred. Legacy Markdown files require manual removal under the no-bulk-file-deletion rule. Original sources, exported notes and retained catalogs are not erased. Deleting an older batch preserves current runtime usage; record mutations remain serialized and stale confirmations fail. This is application-history removal, not secure erasure of external backups or backend logs.
