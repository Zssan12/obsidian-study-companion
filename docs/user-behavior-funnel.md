# Study Companion 用户行为漏斗

分析日期：2026-09-15。依据本仓库实现，不是 KnowledgeOps Agent。当前无产品行为遥测，以下流失判断是待验证假设，不是实际转化率。子 agent 首次重试分析了错误仓库；本报告由主 agent 重新核对后整理，不能视为该子 agent 的有效结论。

## 用户与核心价值

主要用户假设：已经使用 Obsidian、阅读 Markdown/PDF 的自学者，希望遇到不懂的内容时直接追问，保留出处，并在下次学习时接上进度。官方 CLI 安装及账号要求使第一批适配人群更接近已有模型工具经验的用户；不能假设普通学习者都能完成配置。

核心成功是“解决一个具体学习问题，并能继续学习”，不是产生更多消息、收藏或 token。获得正确回答也不等于已经掌握知识。

## 两条入口，三条后续分支

快速入口：启用插件 → CLI 可用 → 选一段资料 → 获得可核验的解释。
课程入口：打开当前 PDF → 点击“梳理全文” → 准备原文 → 生成目录 → 选择主题 → 获得可核验的解释。
两者共享首次价值，不能强迫只想问一句的用户先生成完整目录。

| 阶段 | 用户目标与可观察动作 | 已有实现 | 待验证的流失原因 |
| --- | --- | --- | --- |
| 配置 | 插件启用，所选 CLI 能调用 | 设置支持路径、模型、推理强度；账号由外部 CLI 管理 | 配置与登录的错误可能直到发送才暴露；安装不是激活 |
| 资料就绪 | 明确选中了哪些材料 | 文件绑定、选区、PDF 页码、折叠预览 | 打开文件和实际提供正文容易混淆；长 PDF 的首次处理需要等待 |
| 首次价值 | 完成一个有依据且对问题有帮助的回答 | 主线、引用、实际工具轨迹、自动按需检索 | 无关检索、等待、来源错配或难懂的回答造成退出 |
| 深入理解 | 继续问或针对局部发起 Quick Ask | 主线历史、独立持久侧线、换种讲法、举例 | 用户可能不知道该在主线还是侧线继续；反复追问也可能说明前文没讲清 |
| 内容沉淀 | 收藏或将内容写入笔记 | 星标、收藏批处理、对话摘要预览与合并 | 收藏到最终笔记仍有多步；全文合并与摘要整理两条路径的结果容易混淆 |
| 返回学习 | 重新打开原资料并继续未完成问题或主题 | 可搜索历史、资料绑定、课程进度和侧线恢复 | 找得到历史不等于知道下一步该做什么 |

首次价值后应分支观察：直接继续阅读、局部追问、整理笔记。收藏和笔记不是所有用户必须经过的步骤，不能把不收藏算作流失。

## 优先改进

1. **缩短首次有效回答路径（高优先级，中等工作量）。** 在空状态提供“选中文字解释 / 打开 PDF 直接提问”两个明确入口；提供可区分 CLI 不存在、未登录、服务失败的检查与恢复指引。先观察 5 位目标用户独立完成一次真实任务，记录卡点和首次有用回答耗时。不要为测试引导默认上传私有资料。
2. **让资料范围和等待过程可理解（高优先级，中等工作量）。** 当前已删除手动联网与同文件夹开关，并展示真实运行状态，这是已完成的改进。下一步验收：选区是否被提供、实际读了哪个文件、请求失败如何恢复，能否被用户正确说清。不要用“能力可用”冒充“本轮已使用”。评估自动检索的证据收益和额外等待，简单解释维持直接回答路径。
3. **打通“下次继续”与整理后的返回路径（中优先级，中等工作量）。** 利用已有历史和主题状态提供“继续上次主题 / 打开关联笔记”的明确入口。收藏列表可以显示尚未整理的内容，但不要把收藏计数当作学习成果；先验证用户找回未完成问题是否困难，再决定是否增加入口。无需重新实现本来已经存在的会话历史。

暂不优先增加技能种类、微调或更多功能开关。这些不能直接验证上述漏斗瓶颈。

## 指标口径：先观察，后决定是否实现统计

| 指标 | 定义 | 解释边界 |
| --- | --- | --- |
| 首次配置成功率 | 测试中 CLI 检查成功人数 / 开始配置人数 | 按已有 CLI 与首次安装两类分开 |
| 首次有用回答率 | 完成指定学习任务且用户确认有帮助的人数 / 资料已就绪并尝试任务人数 | 生成完成、引用合法只是技术代理指标，不代表有帮助 |
| 首次价值耗时 | 从开始配置、从资料就绪分别计时到首次有用回答 | 两个起点分别报告，避免隐藏配置成本 |
| 检索收益 | 需要查证的任务中取得相关证据的次数 / 实际检索次数 | 联网成功不代表证据支持结论 |
| 追问情况 | 首次回答后继续问的人数 / 首次回答人数，同时记录追问原因 | 深入理解和纠错重试分开，不追问也可能成功 |
| 整理完成率 | 笔记写入成功次数 / 用户明确开始整理的次数 | 收藏不作为分母；预览取消不必然是失败 |
| 返回继续率 | D1/D7 回来继续原资料有效学习的用户 / 对应到期激活 cohort | 没有回来可能是一次性任务结束，结合访谈解释 |

如将来设计本地事件，可用 cli_check_result、source_ready、answer_finished、source_opened、quick_ask_started、favorite_changed、note_merge_finished、study_resumed。每个事件需定义触发时机、失败类别、去重规则和分母；不要把每次界面渲染当一次行为。默认不采集正文、问题、文件名/路径、URL、账号或原始错误；目前只建议在同意参与的用户测试中手工记录，本次未增加任何埋点或外发。

## 2026-09-15：自动识别 PDF 后的交互复核

本节由主 agent 核对当前 Study Companion 代码。子 agent 首轮又误读了相邻 KnowledgeOps 仓库，该结果不采用。以下是代码能够支持的交互问题和待验证的用户体验假设，不是原生界面实测或转化率结论。

主路径：打开资料 → 提出具体问题 → 获得有帮助的解释 → 回到阅读或继续追问。梳理目录、收藏和笔记都是可选分支。

| 优先级 | 场景与不自然之处 | 最小改进 | 验收任务 | 依据 |
| --- | --- | --- | --- | --- |
| P1 | 新 PDF 的首个问题先缓存所有页，再弹出“新对话”选择后端。用户已经点击发送，等待后又被要求创建对话。 | 已配置默认后端时直接创建并固定归属；确有配置或旧会话归属歧义时在耗时处理前解决。 | 打开新 PDF，输入问题，一次发送完成；不能在准备完成后再要求普通用户选择后端。 | main.ts:91、352；study-thread-view.ts:731 |
| P1 | 自动准备仍遍历所有页。对长 PDF 中一个局部问题，去掉导入窗口并没有消除首次等待。 | 明确页码的问题可先读取可靠页码对应的原文；已有选区优先解释选区；全文梳理保持完整覆盖，无明确定位且无索引时仍如实展示全篇索引进度。避免为提速假装已覆盖全文。 | 300 页 PDF 的“第 90 页这个公式”与“梳理全文”分别计时并验证页证据和覆盖范围。 | main.ts:96、164 |
| P1 | Quick Ask 关闭会调用取消请求；未发送草稿只在浮窗内。用户回原文阅读、关闭再开可能失去未发问题或打断回答。 | 区分隐藏浮窗与停止生成；按资料和侧线身份保存草稿。新选区到来时保留旧草稿并提供明确切换动作，不默默发送或丢弃。 | 输入半句关闭再开；生成中隐藏再恢复；切换选区时检查草稿、回答与来源。 | quick-ask-popover.ts:139、190 |
| P2 | 收藏列表每次勾选都重建全部行，已展开答案随之折叠。用户边读边选择时，操作会打断阅读。 | 按记录身份保留展开状态、焦点与滚动位置；更新选择状态无需重新渲染全部答案。 | 展开两个回答，勾选其中一个，两个回答均保持展开，键盘焦点不丢。 | favorites-modal.ts:99、110 |
| P2 | 收藏搜索无匹配也显示“暂无收藏”，已有内容看起来像消失了。 | 区分初次空列表与搜索无结果，后者显示“没有匹配收藏”及清除搜索。 | 已有收藏，输入无匹配词；清除后原收藏仍在。 | favorites-modal.ts:103 |
| P2 | “整理进笔记”和“整理对话笔记”都叫整理，前者保存完整问答，后者生成摘要，产物预期不清楚。 | 收藏操作叫“将原问答加入笔记”；对话操作叫“生成笔记摘要”。在预览前说明范围和目标笔记，无需增加确认层级。 | 用户未点击前能说出两种操作是否改写内容、保存到哪里。 | main.ts:480；study-thread-view.ts:319 |
| P2 | 回访历史的标题始终使用第一问，虽能搜索后续问题，但列表不显示最后讨论点。很长对话难以一眼找到上次卡住的位置。 | 显示最后一问摘要或最后活动；存在目录时补充上次主题。主线与侧线仍保持各自归属。 | 两天后找到某份资料最后一个未完成问题，不用逐条翻消息。 | conversation-history.ts:32、92 |

建议顺序：先解决“发送后还要创建对话”和局部问题的首次等待，再处理 Quick Ask 的关闭/草稿语义；收藏的展开与空状态可以作为低成本修复。暂不增加新的模式、入口或学习完成率。

后续实施：学习模式已自动建立/恢复当前 Markdown/PDF 的资料对话；新对话继承默认后端，首次发送不再出现创建弹窗。普通模式和显式锁定保留用户选择；建立绑定本身不调用模型。局部 PDF 首次缓存、Quick Ask 草稿及收藏项仍为待改进项。
