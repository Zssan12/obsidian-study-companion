# PDF 证据问答与评测

## 设计目的

用户的问题可能需要选区之外的实验段落或图表，但整份 PDF 持续进入上下文会增加无关信息。当前实现先提供页索引与第一页片段，让模型决定还需要什么证据。应用负责只读工具的执行与范围约束；模型没有文件系统权限。

这是一个受预算限制的应用层 Agent 工作流。没有接入 MCP，没有实现可加载 Skill 系统，也没有微调模型。先验证“获取了什么证据”和“回答是否有支持”，再决定是否将第二种稳定流程提取为 Skill。

## 使用边界

- 插件设置开启“PDF 证据问答（实验）”，重新选择 PDF 页码，使用学习模式。无其他附件的独立主问答（包括课程中的明确页码提问）和 PDF Quick Ask 可进入该流程。
- 主聊天和 Quick Ask 在发送前显示图文/仅文字及原因。扫描页若落入文本流程会阻止点击和回车发送，保留问题和附件；部分页面可提取文字时允许发送，并提示无文字页内容缺失。缺少文件指纹的图文请求提示重新选页。
- 已选页是硬范围：不会自动扩展到其他页、其他资料或全库。扫描页可以按需看图，可另行启用本地 OCR，逐页识别所选范围内原生文字不足 32 字符的页面。
- 最多 4 次读取/搜索、2 张图片、5 次规划调用和 1 次最终回答。规划输出最多 2,000 字符；累计原始文本片段最多 16,000 字符；索引是每页前 60 字符（最多 100 页）；图片每张 Base64 最多 4,000,000 字符，渲染边长最多 1600 像素。已有会话历史仍由 CLI 管理，不承诺整个会话 token 的硬上限。
- 选页指纹、请求时指纹、提取文本均须匹配；使用同一内存 PDF 读取和渲染。Markdown 保存文本和指纹，不归档原 PDF 或图片，因此不承诺视觉证据可跨设备重放。
- 只校验明确的 PDF Markdown 链接范围，不校验自然语言每项结论是否被来源支持。来源中有链接不等于解释正确。

## 结束状态

新规划决策的 `answer` 必须包含 `evidenceStatus: sufficient|insufficient`；`reason` 解释充分依据或具体缺口。缺字段或未知状态直接失败，不从理由文字中猜测。模型声明证据不足仍可正常返回有依据的局部回答，记录的结束状态为 `insufficient`，不改成“充分”或请求错误；达到程序预算则为 `budget`。这些状态描述获取流程及模型判断，不是人工质量认证。

历史记录允许缺少此字段，保持原有 `stop` 不变，避免通过文本猜测重写历史。旧版错误标记仍需人工审阅，不能当成新协议的正确性证据。

## 离线与真实评测

```bash
npm run evaluate:pdf
node scripts/evaluate-pdf-agent.mjs --live --provider=claude --cli=/opt/homebrew/bin/claude --model=sonnet --limit=1
node scripts/evaluate-pdf-agent.mjs --live --provider=codex --cli=/opt/homebrew/bin/codex --model=gpt-5.5 --limit=1
```

默认命令只校验数据，无模型调用。`--live` 使用已登录的官方 CLI；`--limit` 控制案例数，`--arm=selection|text-agent|visual-agent` 选择单组，省略则依次跑三组。每个案例/组有 120 秒总超时；认证错误停止整次实验。模型、推理强度和题目在各组保持一致；输出同时记录请求模型和实际报告的用量模型，不应把别名当成实际模型身份。

`tests/fixtures/pdf-agent/cases.json` 含 24 个合成问题，覆盖文字、图表、证据缺失、越界请求、综合问题及追问。图表数值只在 PNG 中；参考答案和人工评分规则不进入模型输入。结果写入带时间戳的 `artifacts/pdf-evaluation/`，包括答案、动作轨迹、用量、耗时与人工待评分字段。

三组含义：

| 组 | 模型可获得的证据 |
| --- | --- |
| selection | 第一页文本，无工具 |
| text-agent | 所选页索引、按需文本检索，无图片 |
| visual-agent | 相同文本能力，加按需图片 |

此评测使用注入的文档端口，**不证明 PDF.js 在 Obsidian 中的渲染行为**。合成 runner 暂时只支持整页图片；裁剪需单独在宿主测试。数字匹配只是诊断，不能把匹配率当成准确率。

## 人工评分

对每组答案隐藏组名，分别评分：正确性、引用支持、无依据断言，0/1/2（2 为最好）。记录具体错误句和证据页，不只记录总分。成本用实际 input/output/cache token 与耗时分开报告，不将 token 直接转换为订阅扣费。

初步 smoke 后应加入约 20 个来自实际学习材料的固定问题，并在运行前锁定问题与评分规则。保留无法回答、图表模糊、选区不充分的样本。至少重复运行以观察模型随机性；不能用一次合成案例推断真实学习质量提升。

## 本次发现与面试讲法

一次真实 Claude 图表问答主动读取第 3 页图片，识别了 Baseline 62%、Method 79%，并给出了正确图表链接。然而它额外把第一页的“比较时应使用相同测试集”写成“可以确认本实验用了相同测试集”，而真正的实验协议在尚未读取的第 2 页。这个例子表明：结构化页码检查通过，仍可能出现语义证据不足。

据此，最终回答提示明确区分定义/规范与实验事实，并约束无关扩写。这是一项待进一步评测的提示调整，不能声称消除了幻觉。原始失败案例保留在验收记录中。

面试可以讲已实现的事实：模型决定补充证据、程序保证读取边界、图文输入共享来源版本、规划与回答会话分离、用对照实验区分检索收益和视觉收益。不要写准确率提升百分比，也不要把该流程称为微调、MCP 集成或通用 Skill 调度平台。

Codex 图片输入参数依据：[官方 CLI reference](https://developers.openai.com/codex/cli/reference/)。本地 CLI 的 `exec --help` 与 `exec resume --help` 已核对；真实认证结果另见验收记录。

## 直接供给与 OCR 边界

最多两页、文字合计不超过 16000 字符且允许图片时，直接提供原文与原图，省去规划调用。结束状态 provided 只表示已提供证据。最终提示要求逐项核对轴、单位、图例与数值；页码验证不能证明每项解释得到原文支持。

本地 OCR 默认关闭，需要 Tesseract 和对应语言包。逐页限时 30 秒，可取消，以无 shell 子进程读取 stdin PNG、输出 TSV，不创建临时图片；输出有大小限制。原生文字保留，识别文本另存并标识配置与置信度。置信度不是正确率。扫描页、小标题页可识别；原生文字达到 32 字符的混合页不会自动 OCR。手写、公式、复杂布局和小数字仍可能遗漏。选择全文可识别其中的低文字页，但不是对每页强制 OCR。
