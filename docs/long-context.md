# 长上下文处理

PDF 请求和指定回答追问先刷新持久聊天记录，再派生主题与背景；异步准备期间相关历史改变时，派发前拒绝旧请求，要求重新选择，不自动重试。

Codex 主线的成功检查点保存该临时线程实际接收过的 PDF 页码与版本元数据。有效续聊允许引用当前证据及此前传入同一线程的同版本页面；历史编辑、删除、重启、失效或 PDF hash 改变后重建，不从旧问答元数据继承引用权限。直接回答的新线程只有旧问答时，也不能将旧页码当作已取得的原文证据，需要原文时应重新读取。Quick Ask 保持当前选区范围。允许页码只证明来源身份与曾提供范围，不保证自动压缩后逐字保留或论断正确。

完整保存与每次模型输入分开处理。PDF 按文件指纹和页码缓存到 vault 的 Study Companion Cache；同版本导入复用页面，缺失缓存需重新导入。文件上限 256 MiB、10,000 页，单页提取仍限 60,000 字符，扫描页不自动 OCR。

目录按估算 30,000 token 的原文预算分批，额外为指令与页码保留余量；普通课件可一次生成，不再追加章节分组调用。每批默认 4–8 个较粗的学习主题，少量内容可更少；定义、推导、证明和例题尽量合在同一主题。校验最多 8 个主题、所有有文字页覆盖及 6,000 字符输出预算。超长单页仍分段，大文档仍逐批处理并复用成功缓存；不会为了减少调用丢弃后半部分。跨批相近主题尚未自动合并。旧目录与学习进度保留，新生成使用独立缓存版本。主题原文约 24,000 字符以内直接提供，超限则分批摘要覆盖主题所有页；全文总结也逐批读取并递归汇总。

普通文字问答使用受预算控制的模型规划：从现有目录（没有目录则使用页首片段）定位主题，同时扩展中文和英文关键词。定位页面与关键词召回合并，再读取原文。规划输出绝不作为证据；无命中不会任意取第一页。每批目录最多约 14,000 字符，最多 16 批，严格校验返回页面是否属于输入目录。规划结果可以缓存，但增加调用成本；它不是向量检索，仍可能漏检或引入无关片段。

Codex 主线的主题讲解与后续追问共用同一个临时 App Server thread；Quick Ask 按独立 conversationId 保持隔离。每轮重新读取持久聊天记录 并核对完整的可见历史签名。所有 Codex 最终回答在异步准备结束后再次读取记录，与本轮选用线程或重建提示词时的历史快照比较；若已改变，则停止派发，要求用户重新发送，不自动重试，也不继续使用旧摘要或旧准备结果。历史未改变、配置与会话范围一致且连接仍可用时，只发送本轮指令、问题和新证据，不再次拼接全部旧问答。所有新建线程要求服务端确认 ephemeral:true，因此不落成本地持久 Codex 桌面任务；目录、摘要、检索规划和联网辅助调用仍是独立临时线程，不进入教学线程。

插件重启、最多八个空闲连接的淘汰、历史修改/删除/恢复或失败轮次会使旧临时上下文失效。下次从当前仍可见的聊天记录 一次重建，再继续复用新线程；不会用持久化的旧 Codex session ID 恢复不受控历史。模型端长线程可发生压缩，本项目尚未真实验收多小时超长会话。临时线程不等于远端网关不留存，也不会移除以前已出现在桌面端的任务。

重建时，已完成且已保存的全部问答若能放进本轮剩余预算，就直接提供，不额外生成摘要。预算扣除当前资料、指令、问题及追问背景；超预算时保留能容纳的近期完整问答，较早问答分批生成学习状态摘要，并补充有界相关历史片段。几乎没有剩余预算时不生成无法放入的摘要。成功摘要按配置和精确输入缓存，仅实际调用时显示“正在整理较早对话”。按资料、主线/侧线、会话、provider 和主线重置轮次隔离；只读取仍存在且可见的记录，原问答不被摘要覆盖。

Claude 仍沿用此前的托管策略：历史与当前输入累计超过 60,000 字符、此前已托管或索引 PDF 等情形，由应用重建上下文，不恢复 CLI session。这一分支未在本轮改成 Codex 的临时线程机制。

笔记按约 24,000 字符问答批次执行，单条长回答继续分段并保留原 ID；已有笔记最多提供约 6,000 字符相关参考。全部完成后统一预览确认。失败或取消保留成功批次，重新执行复用输入未变的结果；保存前再次检查原记录。

辅助调用估算输入上限 48,000 token，最终回答为 64,000 token；输出另设字符预算。组合证据统一分配约 40,000 token，主资料权重为附件的两倍，未用额度会重新分配。超额资料覆盖所有片段分批摘要，明确标注非逐字原文；最终组装为历史预留空间，历史先舍弃相关片段，再减少近期轮次。ASCII / 非 ASCII 保守估算不是模型 tokenizer，未动态读取模型窗口或精确计算图片 token。极端元数据或异常输出仍可能明确拒绝，不能声称无限输入。

缓存包含本地原文与摘要，采用 vault 的访问控制。模型缓存键包含版本、配置、provider 和精确输入；不自动清理，不后台调用模型。恢复指用户重新执行时复用成功批次，不是自动重试。

合成测试覆盖 300 页、远端页面选择、过长主题、超过 100,000 字符历史和笔记、失败恢复及删除隔离。页面覆盖不等于语义完整；真实 PDF 提取、摘要质量、引用语义和 Obsidian 视觉效果仍需人工测试。

## 上下文用量与引用预览

用量按资料、主线/Quick Ask 和 conversationId 分别保存在内存中。切换资料、普通/学习模式或打开旁路后，各输入框读取自己的最近上报，其他对话的生成不会覆盖它；并发请求的局部更新也只合并到原会话及后端。重置主线、删除或恢复对话仅清除对应缓存。插件重启后等待后端重新上报，不从历史累计消耗还原上下文用量。

主线与 Quick Ask 的环形指示器显示当前资料、会话及后端匹配的最近一次上报；悬停或聚焦查看已用 tokens、总量和比例。未发送的草稿不计入。缺失值显示未知，不按模型名称硬编码窗口容量。Claude 按单条 assistant 消息的输入加缓存读取/创建统计；只有明确单次调用的 result 才能作为回退，多次调用累计消耗不作为当前上下文。切换会话后的 usage-only 事件不继承其他会话的容量或占用量。

Codex 在收到当前 thread/turn 的 `thread/tokenUsage/updated` 时即时刷新圆圈，使用 `last.totalTokens` 与 `modelContextWindow`，回答完成后保留同一份用量。`total` 是跨调用累计消耗，不作为占用；缓存输入已包含在本次统计中，不重复相加。缺失或无效字段清空对应旧值，不能沿用上一次报告假装已知。

当前引用与附件默认折叠为文件名，展开最多展示 15 行，每行最多 240 字符，剩余内容只显示行数。预览截断不修改存储文本或请求预算；导入 PDF 引用不表示模型已读取全文。
