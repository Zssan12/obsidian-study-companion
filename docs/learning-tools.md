# 学习工具

| 工具 | 实现 | 限制 |
| --- | --- | --- |
| Glob | 授权目录内按文件名模式查找 | Markdown；返回最多 50 个路径及剩余数量 |
| Grep | 应用读取候选文件并做关键词匹配，规划器可生成双语词 | 每次最多扫描 200 份、本轮最多 4 MB，返回 10 条带路径与行号的命中 |
| Read | 应用校验相对路径后读取当前文件 | 单文件最多 512 KB，最多 40 行并受输出字符预算约束 |
| WebSearch | 独立 CLI 请求执行原生联网工具 | 按问题自动调用；Claude WebSearch / Codex live web search |
| WebFetch | 独立 CLI 请求读取网页 | 用户给定或本轮搜索结果中的 HTTP(S) URL；Claude WebFetch / Codex 网页打开能力 |

新配置默认只检索当前 Markdown 资料，联网默认按需可用但保守触发。有选区的普通问题直接围绕选区回答，跳过额外检索规划；清除选区后可按需读取当前笔记。用户可在设置中明确选择同文件夹或整个笔记库，也可关闭笔记检索。已有有效设置会保留，不再强制覆盖为同文件夹和联网开启；此前自动生成的 folder/true 配置会保留；若不需要其他笔记，应在设置中改为“仅当前资料”。联网可保持自动，也可关闭。没有来源的普通对话默认不搜索本地文件夹。隐藏路径、父目录穿越、生成的 Study Companion 记录与 Study Companion Cache 被排除。文件列表每轮重新获取、正文只在本轮缓存；不是持久向量索引，也没有后台扫描。

工具服务适用于普通主线、学习问答和 Quick Ask；生成课件目录或显式主题讲解不加入额外工具。PDF 内页检索仍由原有 DocumentLibrary/PdfEvidenceAgent 负责，Glob/Grep 不扫描 PDF 二进制。

## 请求与证据

StudyController 在发送时冻结检索设置、来源和会话归属，向 LearningTools 注入捕获的 backend。规划器只输出 JSON；应用验证后执行白名单动作。最多四次规划/动作，最多 90 秒，工具正文总计最多 8,000 字符。单个联网动作中，后端的工具完成事件再限制为最多四次；停止会取消当前请求。工具结果进入最终输入预算，托管历史预留空间，超过最终预算则明确失败。历史工具结果也计入是否需要托管压缩的判断；压缩后只重建问答历史，不无限重放旧检索原文，需要时重新读取。

每次规划/联网都是独立 CLI 请求，不恢复主线或 Quick Ask session。只有最终回答的 session 可更新对应对话。Web 请求只接收搜索词/URL与固定指令，不接收整份本地笔记或历史。模型主回答没有原生文件、shell 或联网权限。

工具轨迹以验证后的 toolTrace 保存到记录 frontmatter：名称、参数、结果、错误、真实读取路径和起始行。Read 是文件原文；Grep 是定位线索；WebSearch/WebFetch 正文是独立检索助手基于工具结果给出的摘要，不能称作网页逐字引文。成功的原生工具事件是接受网络摘要的必要条件，但不等于语义准确性验证。

插件设置提供“笔记检索范围”和“按需联网（保守）”；解析和重载尊重保存值。输入框上方显示当前动作和本轮已使用的来源类别，错误明确显示；工具轨迹默认折叠，最多 15 行预览，Read 可打开真实笔记。预览截断与请求/存储预算分开。

## 检索分流、证据编号和整轮统计

- 解释选区、换个方式讲、举例按钮以显式 learningIntent 跳过检索规划；已有选区时，所有检索范围下都默认直接回答，不再依赖解释措辞白名单；只有当前问题明确要求找笔记/读原文或符合外部检索条件时才进入规划器。检索范围只限定可以读哪里，不代表每轮都应该检索。没有选区时不使用这条捷径。该分流只影响关联笔记/网页工具，PDF 已有证据准备流程保持独立。
- 成功 Read 的可见原文按本轮顺序分配 S1 等编号；保留实际起止行、文件 mtime/size 和被读取的片段。读取前后文件元数据不一致则拒绝该次读取。mtime/size 不是加密哈希，也不保证文件未来保持不变；历史片段用于核对当时证据。
- 模型输出方括号证据编号，应用生成真实文件链接和行号。未知编号、未读取笔记、未在原文出现的章节标题会被移除并令记录显式失败。校验覆盖 wiki、Markdown 内联/引用定义、HTML anchor；代码块与行内代码不作为引用。该校验验证定位身份，不证明原文支持模型结论。网络 URL 仍是独立联网助手提供的来源，不纳入本地证据编号。
- 没有读取到原文时不提供编号示例，避免模型模仿不存在的引用。链接语法示例要求放在代码中，以免生成可点击的虚构笔记链接。
- 正在生成的主线和 Quick Ask 也显示工具记录；新增步骤不折叠用户已经展开的旧步骤。已保存问答增加可展开的整轮调用统计，包括准备、检索规划、联网、回答次数和耗时。token 只累计实际 usage 上报，并显示上报覆盖率；输入/缓存分别展示，不相加推算费用，也不把累计消耗当上下文占用。

## 固定评测

自动模式下，完整的纯数字算术问题（例如 `2+2`、`2+2等于几？`、`Reply with only the result: 3+3.`）由本地规则直接进入回答，不再额外调用模型规划检索，也不为它准备新的 PDF 证据。封闭四则运算语法直接使用本地有理数计算，不调用模型、不执行代码；不支持的语法回退模型。结果落盘，下一次模型请求重建包含该轮的历史。含原文/联网要求、变量或指代的混合问题不使用此捷径；显式资料模式、附件、课程讲解及 Quick Ask 的证据边界优先。

`tests/fixtures/learning-tools/cases.json` 固定 20 个场景，数据是合成笔记与公开 Obsidian 网页，不是用户真实笔记。覆盖直接学习动作、中英文检索、多来源、缺失、范围隔离及联网。

- `node scripts/evaluate-learning-tools.mjs`：只校验数据集，不调用模型。
- `node scripts/evaluate-learning-tools.mjs --live --provider=claude`：运行真实 CLI，逐题保存动作、最终回答、引用校验、整轮统计。可用 `--model=精确模型名` 固定模型；未指定时记录为 CLI default。`--ids=case1,case2` 可定向复测，`--limit=N` 限制数量。
- 自动检查路由、实际读取目标、范围、真实联网结果、引用格式和完成状态。解释质量及来源能否支持结论仍需单独评分，结构通过率不能当作回答准确率。
- 各次原始报告保存在 `artifacts/learning-tools-evaluation/`。初次报告与复测保留，不覆盖失败记录；不同运行时间不能用来声称因果性的延迟提升。

## 2026-09-15：保守自动联网与 Claudian 参考

阅读 [Claudian](https://github.com/YishenTu/claudian) 的 `bb9ddf0fd65665bff43ace821d0c829769fd68de` 版本：

- [ClaudeExecutionRequestEncoder.ts](https://github.com/YishenTu/claudian/blob/bb9ddf0fd65665bff43ace821d0c829769fd68de/src/providers/claude/execution/ClaudeExecutionRequestEncoder.ts#L149) 构造带会话恢复和工具策略的 SDK 请求；默认路径没有另加网页检索规划请求。
- [ClaudeInteractionHandler.ts](https://github.com/YishenTu/claudian/blob/bb9ddf0fd65665bff43ace821d0c829769fd68de/src/providers/claude/execution/ClaudeInteractionHandler.ts#L29) 将工具权限检查绑定当前 turn，并处理 SDK 权限交互，不能笼统说始终免确认。
- [ToolCallRenderer.ts](https://github.com/YishenTu/claudian/blob/bb9ddf0fd65665bff43ace821d0c829769fd68de/src/features/chat/rendering/ToolCallRenderer.ts#L705) 展示实际 WebSearch/WebFetch 事件。

借鉴的是“联网能力随对话可用、实际调用才展示”的交互。Study Companion 保持独立联网会话，仅传查询词或 URL，不传整份笔记或对话历史，没有复制上游实现代码。

`web-search-policy.ts` 按当前问题的外部资料、时效事实、网址读取信号决定是否允许网页规划。“不要联网”优先；短确认如“好，查一下”只对照当前会话紧邻上一轮，选区中的命令文本不作为联网意图。控制器按 unit/kind/conversation/provider/history epoch 隔离历史，重置、换资料和 Quick Ask 不借用另一条对话的查询提议。

这是保守文本规则，不是完整语义分类，复杂隐含措辞可能漏判。允许进入规划后，模型仍应优先直接回答，只在确需外部证据时联网。一轮最多一次独立搜索任务和一次网页读取任务，不重复搜索或自动重试；各后端单任务的原生工具预算仍保留，不能将一次任务等同于一次 HTTP 请求。上一轮用户提供的 URL 仅在同会话内可继续读取，模型凭空提供的 URL 不因此获得许可。

本轮 512 项自动测试、类型检查、Lint、模块边界和构建通过。真实 Claude Sonnet/low 的三个服务层检查：选区解释 1 次调用、10.2 秒；搜索 4 次调用、45.9 秒；网页读取 4 次调用、43.0 秒，全部通过来源/调用结构检查。这是本次观测，不是对照测速或解释质量评分。短确认的会话隔离经过自动化测试；本轮未完成原生 Obsidian 重载和交互验收。原始结果在 `artifacts/learning-tools-evaluation/2026-09-15T15-16-22-899Z-claude/report.json`。
